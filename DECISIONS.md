# DECISIONS

One line each: decision — reason.

- Read all `design/*.dc.html` before any UI work; design date "Pazartesi, 12 Ekim" coincides with the build date (2026-10-12), so demo seed is relative to "today" — keeps the demo looking like the design on any day.
- Next.js 16.4 (create-next-app) with `cacheComponents`/`partialPrefetching` turned off — app is fully client-side over localStorage; server only renders shells, so the cache-components constraints add risk without benefit.
- Styling: CSS Modules + global token CSS (`src/app/globals.css`) — design is hand-written CSS; modules port it 1:1 without a Tailwind translation layer.
- Theme: `data-theme` on `<html>` set by an inline boot script before paint (no flash); `prefers-color-scheme` CSS fallback when JS is off. The boot script and `src/data/preferences.ts` are the only places reading the theme key — the boot script must run before React.
- Node pinned to 24.x (current LTS on 2026-10-12; Node 26 is not LTS yet). Local dev machine runs 26, which only produces an engine warning.
- `@types/node@24` instead of the scaffold's `^20` — vitest 5 peer requires >=22.
- `typecheck` runs `next typegen` first so route-aware types (`LayoutProps`, `PageProps`) exist without a build.
- E2E server = `next build && next start` on port 3100 (production parity, the build is what Vercel runs).
- Storage layout: one JSON array per table under `anv:t:<table>`, schema version in `anv:meta`; rows are zod-validated on read, invalid rows dropped, unparseable tables quarantined to `anv:corrupt:<table>:<ts>` — the app keeps working with a calm notice instead of crashing.
- Built-in recipes live in code (`src/data/seed`), not in storage; only household custom recipes are stored — keeps storage small and lets the seed improve without migrations.
- Session: sessionStorage holds the per-tab user, localStorage remembers the last login so new tabs and restarts stay logged in; logout only clears the shared fallback if it points at the same user.
- Emails and invite codes compared with plain `toLowerCase()` (Turkish casing turns `I` into `ı`, which breaks ASCII emails); Turkish casing is used for user-facing search/sort.
- Sync: writes publish a coalesced `change` message per tick over BroadcastChannel; `storage` events are a fallback. Presence heartbeats use the same channel.
- Recipes reference a canonical ingredient catalog (`src/data/seed/ingredients.ts`) with base unit, kitchen-measure conversions and pack sizes; the `i()` builder throws on unknown names — this is what makes list aggregation reliable.
- Pantry staples (salt, oil, spices, kuru nane, bayat ekmek) are flagged `staple` and never auto-listed; recipe detail shows them as "Evde var" like the design.
- Design names kept verbatim; long names get a `shortName` for chips/tags ("Tereyağlı pirinç pilavı" → "Pirinç pilavı", "Ezogelin çorbası" → "Ezogelin").
- "Ertesi güne artar" tag is derived from `leftoverFriendly` and appended last (matches the design's card tag order) instead of being stored in `tags`.
- Menemen and other breakfast/one-plate dishes have course `kahvalti` but fill the "Ana yemek" slot and appear under "Ana yemekler" in onboarding, as in the design.
- Shopping list window = today + next 6 days (not the board's "2 back / 5 ahead"); past evenings never add to the list. Dishes sent back to matches by "dışarıda yedik"/"plan değişti" keep their ingredients on the list until placed again or a week passes ("malzemeler listede kalır").
- List quantities are shown as purchase amounts: summed in a base unit, then rounded up to packs (250 g kıyma, 1 kavanoz salça, 10 yumurta) or, for pazar produce sold by weight, to 500 g — reproduces the design's sample list ("Kıyma 500 g", "Domates 1,5 kg", "Arpa şehriye 1 paket").
- "Alışverişi bitir" stores the bought (pack-rounded) amount in the pantry; cooking a dish (rollover of past planned evenings) consumes measured pantry stock; unmeasured "evde var" entries persist until removed.
- Plan transitions are pure functions returning operation lists (`src/domain/plan.ts`); the store applies them through repos — keeps business rules testable and out of components.
- Prep tasks alternate household members in time order per day (first-joined member gets the first task) — reproduces the design (kıyma → Ali, köfte harcı → Zeynep). Night-before = 21:00 the previous day, morning = 09:00, offsets relative to the household dinner time (default 19:30).
- Solo household: a single "Olur" is a match (no partner to wait for); copy switches to singular.
- "Plan değişti → Yarına taşı" swaps with tomorrow's menu when tomorrow is planned, instead of cascading — reversible and never destroys a plan.
- Adding a dish counts as the adder's approval; any menu change resets approvals to the person who changed it.
- Households are capped at 2 members (the design's copy and colors are built around "ikiniz"); a third person gets a calm "Bu ev şu an dolu" state.

- Route protection is client-side (`Guard`): data lives in localStorage, so the server can't know the session. Anonymous → `/giris?next=…`; signed in without a household → `/onboarding/1`.

## Round 2

Data-model plan (each change ships with a versioned migration in `src/data/migrations.ts` + a unit test, and is mirrored in `supabase/schema.sql`):

- v3 — Recipe gets `sourceUrl`, `sourceAuthor`, `sourcePlatform` (instagram/youtube/tiktok/web); old link-shaped `source` text moves to `sourceUrl` — credit needs the link and the creator separately; `source` stays a free-text note ("Annemin defteri").
- v3 — New `importLog` table (household, platform, path `llm`|`rules`, by, time) for "Bu ay N tarif içe aktarıldı" in Ayarlar; it stores no link or caption — usage counting needs neither, and captions are someone else's text.
- v4 — Recipe `leftoverFriendly: boolean` becomes `leftoverPolicy` (`none` | `lunch` | `store`) + `leftoverDays` (1–4, default 2); old custom recipes: true → `lunch`, false → `none` (exactly the old behaviour). Built-in defaults are a data table (`src/data/seed/leftovers.ts`), not code.
- v4 — Household gets `lunchAtHome` (`yes` | `no` | `some`) + `lunchDays` (weekday numbers, 0 = Pazar); default `yes` keeps today's "Öğlen · …" behaviour.
- v4 — PlanDay `leftovers: boolean` becomes `leftoverChoice` (null = follow defaults, or `none` | `lunch` | `fridge` | `discard` | `eaten`); old true → `lunch`, false → `none`, so stored weeks look exactly as before. The effective leftover is derived (pure rule in `src/domain/leftovers.ts`), never stored twice.
- v4 — PlanItem `source` gains `leftover`, plus optional `leftoverFrom` (the evening it was cooked): a dolapta dish dropped onto a day is a normal plan item, so menus/board/Bugün need no special casing; list, prep tasks, cook log and pantry use skip it.
- v5 — New `cookingSessions` table (household, key = menu date or recipe id, user, phase, per-dish step positions, checked ingredients, timers with absolute `endsAt`, started/finished) — syncs to the other tab through the normal change bus and survives reloads.
- Activity gains `leftover.set`, `cooking.started`, `cooking.finished`, `recipe.imported`; old rows stay valid (the enum only grows).
- Import step durations: when the LLM returns a duration the step text lacks, it is appended as "(20 dk)" instead of adding a parallel `stepMinutes` array — the cooking mode parses durations from text anyway, and the form stays one textarea per step.
- Import fetches only official/public endpoints: TikTok oEmbed, YouTube Data API v3 (with `YOUTUBE_API_KEY`) or YouTube oEmbed, and schema.org JSON-LD on ordinary recipe sites. No Instagram/TikTok HTML scraping, no video/audio download, no unofficial APIs — terms-of-service risk for a product that wants platform and creator goodwill.
- Instagram import never calls Meta (oEmbed no longer returns caption or thumbnail): the link becomes a card and the paste box opens with a short explanation.
- Pasted caption text always wins over fetched text; schema.org recipes are used as-is (no LLM call needed); otherwise LLM when available, rule parser as fallback. The pipeline (`src/domain/import/pipeline.ts`) takes `fetch` and the LLM structurer as injected deps, so it is tested without network.
- Durations: ranges use the upper bound ("10-15 dk" → 15), anything over 12 h ("bir gece") is not a timer, seconds are kept for short timers. Shared by import and cooking mode (`src/domain/durations.ts`).
- Ingredient amounts: ranges use the upper bound ("2-3 diş" → 3) so the list does not come up short; "1.000" is read as a thousand (Turkish thousands separator).
- Catalog matching: exact catalog names first (short names like "Un" must be whole words, so "unutmayın" is not flour), then everyday aliases ("soğan" → Kuru soğan, "salça" → Domates salçası). Unknown items stay free text. Water is dropped from imported ingredients (never bought).
- Caption reminders ("…çıkarmayı unutmayın") become prep-ahead items, not steps.
- Claude import: `claude-haiku-5-5`, forced tool use (`tarif_taslagi`) with a JSON schema mirroring `importedRecipeSchema`, `max_tokens` 1500, SDK retries off and one explicit retry on invalid output, then the rule parser. Timeout 15 s for the whole request (platform fetch + LLM share one AbortSignal).
- Rate limit: 30 LLM imports per household per day, in memory per server instance (keyed by household id, IP as fallback); over the limit the draft still comes from the rule parser with a calm note. Moves to a DB counter with Supabase.
- The web adapter fetches arbitrary user links, so it goes through `guardedFetch`: http(s) only, DNS-resolved private/loopback/link-local addresses refused, redirects re-checked (max 3). Platform endpoints (TikTok/YouTube oEmbed, YouTube API) use plain fetch.
- Logs never include caption text or the LLM's input/output — only error class names.
- `src/server/import/*` holds the handler, kept out of `route.ts` because Next route files may only export route fields; the handler takes fetch/env/client as deps for tests.
- Import screen is `/tarifler/ice-aktar` (inside the guarded app; the login keeps the shared query through `?next=`). The draft opens in the existing `RecipeForm` (new optional `header` slot for the source card + "Kontrol edip kaydet"), so imported recipes are edited with exactly the same fields and validation as hand-written ones.
- The paste box is a disclosure ("Açıklamayı yapıştırmak istiyorum"), always available, opened and focused automatically when the source gives no ingredient lines.
- Recipe credit line: "Kaynak: @author · Platform" with "Videoyu aç"/"Sayfayı aç"; the creator's oEmbed thumbnail is shown on the import card only (the recipe page keeps the `.ph` placeholder like every other recipe).
- Import usage in Ayarlar counts drafts produced this month (both paths, with the "akıllı okuma" share); counting happens when a draft is produced, not on save, because the LLM cost is spent then.
- Web Share Target: manifest `share_target` GET → `/tarifler/ice-aktar?title&text&url`; Android often puts the link inside `text`, so the page extracts it. iOS Safari has no share targets: iOS users paste the link.
- App icon: a plate with fork and knife on the tomato token (`public/icon.svg`, rasterized to 192/512 PNG); no maskable variant because the icon has rounded transparent corners.
- Imported time split: with a known total, prep is a third of it (5–15 min) and the rest cooking; otherwise cooking is the sum of step durations and prep 15 min.
- Platform names in the source card keep their own casing: Turkish uppercase would print "TİKTOK".
- Leftover outcome order: per-evening choice → recipe default → household lunch setting. "Nobody home for lunch" always turns a lunch into a dolapta item (even an explicit "Yarın öğlen"), because the setting describes the household; the choice buttons hide "Yarın öğlen" on such days (R6).

## Round 2.1

- **Provider interface** lives in `src/server/llm/`: `structureRecipe(text, meta, { providers, signal })` → `{ draft, provider }`. Providers implement `LlmProvider.call(input, { signal, retry })` and return raw JSON or throw `ProviderError(kind)`; the chain owns validation, the single retry and fall-through, so each provider is ~50 lines of transport. The rule parser is the chain's last step, not a provider object, because it needs no input restriction, can't fail and is also what the pipeline uses when no structurer is configured.
- **One prompt, one validator, one schema:** `prompt.ts` holds the system prompt, the user-message builder and `RECIPE_JSON_SCHEMA`; Claude uses it as the forced tool's `input_schema`, Gemini gets it converted to its OpenAPI-subset `responseSchema` (`type: ["string","null"]` → `nullable: true`). `validate.ts` (tidy → zod `importedRecipeSchema` → durations into step text) is shared. The retry note was reworded so it isn't Claude-specific ("şemaya uyan geçerli bir tarif taslağı").
- **Gemini over REST, not an SDK:** one `fetch` to `v1beta/models/{model}:generateContent` with `x-goog-api-key`. No new dependency, trivially mockable, and the privacy test can inspect the exact body. Default model `gemini-3.1-flash-lite` (spec), `GEMINI_MODEL` overrides; temperature 0.2, 2048 output tokens.
- **Fall-through rules:** 429 / `RESOURCE_EXHAUSTED` (any status) → quota, no retry, next provider. Timeout → next. Other HTTP/network errors → next (a 503 on Gemini shouldn't cost the user the smart draft when Claude is configured). Invalid JSON or schema-invalid output → one retry with the note, then next. Each provider attempt gets its own 7 s budget (`PROVIDER_TIMEOUT_MS`) inside the request's 15 s deadline, so a hanging Gemini still leaves time for Claude; once the overall deadline passes, the chain stops and the rule parser answers.
- **Privacy — what leaves the server:** providers receive `ProviderInput = { text, platform }` only. The household id is used only as the rate-limit key. The YouTube video title (public content of the post, not user data) is folded into the caption as its first line when it isn't already there, instead of a separate "Başlık" field, so the request contains exactly caption + platform. Before 2.1 Claude got the title as a separate line; same information, one shape now. The test asserts the full Gemini body (keys, system text, single user part) and that household id, cookie email, IP, author and link are absent.
- **Response shape:** `provider` (`gemini`|`claude`|`rules`) is added next to the existing `path` (`llm`|`rules`), which stays because the draft screen's wording keys off it and the spec forbids import UI changes. `counted` now carries `{ platform, provider }`.
- **Data model:** `importLog.path` → `provider` with localStorage migration v6 (`llm` → `claude`, since Claude was the only LLM before 2.1; `rules` → `rules`) + unit test; Postgres enum `import_path` → `import_provider` updated in place in `supabase/schema.sql` (never deployed), noted in `docs/SUPABASE_MIGRATION.md`.
- **Ayarlar line:** "Bu ay 12 tarif içe aktarıldı (11 Gemini, 1 kural)." Order Gemini, Claude, kural; zero counts omitted; the split is shown even when everything was "kural" (consistent, and it tells the owner smart reading is off). Helper `importUsageText` in `src/domain/import/usage.ts` (Next page files can't export helpers).
- **Rate limit unchanged:** 30 smart imports per household per day across the whole LLM chain (one token per import, whichever provider answers).

## Cooking mode: "Başlamadan önce" instead of a mandatory Hazırlık

- **Hazırlık is no longer a step.** On opening cooking mode (`/pisir/…`) we compute what is actually missing (`missingForCooking` in `src/domain/cooking.ts`): prep-ahead tasks for that evening not marked done, plus menu ingredients that are neither ticked as bought in Liste nor "evde var". Staples (salt, spices) never count. The per-ingredient rule is the recipe page's existing `ingredientStatus`, so Tarif, Liste and cooking mode agree on what "missing" means; an ingredient still on the list but unticked is missing ("listede").
- **Nothing missing → step 1.** `startCooking(key, ids, { skipPrep })` creates the session directly in `steps`, or moves an open session still sitting on the heads-up to `steps`. The decision is made once, when the screen opens: resolving the last item on the heads-up does not jump away (the cook may still be reading), it shows "Hepsi tamam" and the primary button changes from "Yine de başla" to "Başla" (nothing is being skipped any more).
- **Something missing → "Başlamadan önce · N eksik"**, prep first ("Yaptım"/"Çıkardım"), then ingredients. Each has **Evde var** (`markHave`, synced like everywhere else). **Listeye ekle** is shown only when the item isn't on the list yet (a recipe cooked outside the plan); for planned menus everything missing is already on the list, so the row says "listede" instead of offering a button that would do nothing. "Yine de başla" always works and is the only primary button.
- The old tap-to-tick checklist (`session.checked`) is gone from the UI; the field stays in the schema (harmless, no migration needed) so older sessions still parse.
- **Malzemeler sheet:** a small button beside the step label (outside the animated step so it doesn't slide) opens the existing `Dialog` (bottom sheet on phones) with the full merged list, amounts and dishes. Arrow keys don't change steps while it's open. The sheet's scrolling body is focusable (`Dialog readOnly`) because it has nothing to tap — axe `scrollable-region-focusable`.
- **"Pişirmeden 1 sa önce":** `offsetLabel` now says "Pişirmeden 45 dk önce" / "Pişirmeden 1 sa önce" / "Pişirmeden 1 sa 30 dk önce" (a bare "1 sa önce" read like "1 hour ago"). One function, so the heads-up, Bugün's "Yarın" line and the Tarif timeline all change together. Capitalised like its siblings "Sabah" and "Akşamdan", which start the label in the same places.

## Leftovers are never guessed ("Artmaz" by default)

- **Default is "Artmaz / hepsi biter" everywhere:** new recipes (already), imported drafts (the rules and LLM paths both went through `toRecipeDraft`, which guessed "store" for anything but salads — removed; the LLM prompt/schema never had a leftover field), and the 100 built-ins. The user decides when a dish is kept: on the recipe ("Saklanır"/"Ertesi gün öğlen yenir") or per evening.
- **Built-ins keep their shelf life.** `src/data/seed/leftovers.ts` no longer holds a policy per recipe; it is now `KEEP_DAYS` (1–4 per recipe). How long kuru fasulye keeps is a fact about the dish, not a guess about the household; it's used only after someone keeps a leftover ("Dolaba kaldır" → "Perşembe'ye kadar"). The demo's Friday dolma (explicitly "Dolaba kaldır") still shows on Monday because dolma keeps three days.
- **Migration v7:** built-in recipes are not stored (they come from code; a household edits its own copy, the repo refuses updates to built-ins), so the code change itself resets them. v7 covers any stored built-in row (`householdId === null`) still holding the old R5 policy → `none`. Household recipes — created, copied or edited — keep their stored choice, even if a copy inherited an R5 value: there is no way to tell an inherited value from a deliberate one, and the user owns those recipes. Supabase: seed with `none`; the doc has the one-line update for an already-seeded DB.
- **"Afiyet olsun" question:** pre-selects the evening's explicit choice, otherwise what the recipe says — which is now Artmaz ("Hiç kalmadı") unless the household itself set the recipe to Saklanır/öğlen. I didn't force "Hiç kalmadı" over a recipe the user deliberately marked "Saklanır": the screen would show one thing while Bugün/Dolapta derive another if they leave without tapping.
- **Form control:** "Artarsa ne olur?" is a `ChoiceChips` radio group (new `src/components/ui/ChoiceChips.tsx`): the leftover chips' look (olive when chosen), three options side by side, wrapping on narrow screens; one tab stop, arrows/Home/End move and select, like native radios. "Kaç gün içinde" renders only for Saklanır (it already did; the layout no longer reserves a column for it).

## Dark-mode selects

- The roots already declared `color-scheme` (light/dark); an explicit "Açık" choice on a dark system now also sets `color-scheme: light`. The bug was the controls: `select` inherited the light ink with a transparent background (from `.input`), so the browser painted the native list on its default white with our light text. `select`, `option` and `optgroup` now get `--surface`/`--ink` globally; the chosen option gets `--olive-soft` (Chromium needs a gradient to override its pale-blue system highlight, and `-webkit-text-fill-color` for the text).

Ayarlar has no selects (chips). It fails on the old CSS (option background `rgba(0,0,0,0)`).
- A native popup is drawn outside the page and can't be captured by a page screenshot (and there is no virtual display here; I didn't open windows on the desktop session). `npm run screenshots` › `tarif-yeni-select` expands the Öğün select in place (`size=N`), which draws the options with the same option styles.
- Also fixed: the form's "Ne zaman" options still said "1 sa önce"; they now read "Pişirmeden 1 sa önce" like the rest of the app.

## Import draft quality

- **Why Kaynak was empty:** `toRecipeDraft` always set the free-text `source` to "" (the credit lived only in hidden `sourceUrl/Author/Platform`), on every path — not only the paste fallback. Now `sourceLabel` fills it: "<Platform> · <author>", the platform alone without an author, the site name for web pages, and "Yapıştırılan tarif metni" for text pasted with no link (the spec says never empty; that is the only honest label without a link). The paste-fallback request re-fetches the link, and a platform can answer less the second time (rate limit, timeout): `keepSource` keeps the first answer's author/title/thumbnail for the same URL.
- **Recipe page shows the Kaynak text** ("Kaynak: YouTube · Yemek.com") so a user's edit is what people see; recipes imported earlier (no text) keep the derived "Kaynak: @author · Platform". The wording order follows the new field ("Platform · author"); the e2e/component expectations were updated.
- **Thumbnail:** stored as `sourceThumbnailUrl` (the platform's own URL from oEmbed/og:image). Not displayed on the recipe page yet (the design uses the `.ph` placeholder, no web photos) and never re-hosted.
- **Tag vocabulary uses the app's existing words.** The spec's list says "Tencerede, Balıklı, Etsiz, Baklagil", but 44 built-ins are tagged "Tencere" and others "Balık", "Vejetaryen", "Bakliyat"; mixing both spellings would split Tarifler's tag filter. So the canonical tags are the existing ones and the spec's words are synonyms (also accepted from an LLM). "Etli" is included next to Kıymalı/Tavuklu (8 built-ins use it). Rule keywords are deliberately conservative: bare "et" counts only as an ingredient (in sentences it's the verb: "marine et", "servis et"), hot-oil temperatures ("180 derece kızgın yağ") don't mean Fırında, "haşlanmış nohut" doesn't mean Haşlama, taze fasulye/bezelye aren't Bakliyat, and Vejetaryen needs ≥3 ingredients with no meat, chicken, fish or stock.
- **Times:** new optional `waitMinutes` on recipes ("Bekleme (dk)" in the form, "+ 1 sa 30 dk bekleme" on the recipe page; not part of the menu's time to table). Migration v8 (optional fields, nothing to convert) with a read-back test; Supabase `wait_minutes`, `source_thumbnail_url`. The fish-and-chips case: soaking (30 dk) and batter resting (1 sa) used to be summed into cooking; now Pişirme 15, Bekleme 90. LLM schema gains `prepMinutes`, `cookMinutes`, `waitMinutes` and the prompt says what counts as cooking and to leave unknown times null instead of guessing.
- **Long-cook hint:** Pişirme > 90 with no step that keeps something on heat for an hour or more → hint text under the field (`aria-describedby`), never a validation error. None of the 100 built-ins triggers it.

## Import: the Yemek.com video with junk steps

- **Which provider, and why:** production answered `provider: "rules"` with `llmAvailable: true` — a Gemini key is set (only Gemini; no Claude fallback) and the chain gave up. The old log line said only the failure kind, so the cause wasn't visible. Providers now carry the HTTP status and the provider's error code (`ProviderError.status/reason`), logged as `[import] gemini gave up (timeout|error 503 UNAVAILABLE…)` and returned in the response as `fallbacks` (no caption text). With that deployed, production showed two problems:
  1. **Timeout:** Gemini 3.1 Flash-Lite thinks before answering by default; even a three-line caption took 6–10 s against my 7 s per-attempt budget inside a 15 s request. Fixes: `thinkingConfig.thinkingLevel: "minimal"` (Google's docs don't list levels for this model; if a model refuses it with 400 INVALID_ARGUMENT the provider retries once with `"low"` and remembers per instance), `maxOutputTokens` 4096 (thinking counts toward it), the last provider in the chain may use the rest of the request, and the request deadline is 25 s instead of 15 s (route `maxDuration` 30). This departs from Round 2's "15 s timeout": with the model's real latency, 15 s for fetch + LLM failed most long descriptions.
  2. **503 UNAVAILABLE** ("model is overloaded"), intermittent and fast (< 1 s): now retried once after 0.8 s before falling through.
- **Why the steps were junk anyway:** with the LLM out, the rule parser took every line after the ingredients as a step — the description has no steps at all (Yemek.com keeps them on the website) — so the link list, "abone olun", "SOSYAL MEDYA HESAPLARIMIZ" and the sponsor's product links became 18 "steps". Even a working LLM was never told not to do this.
- **Written recipe first:** the description's "Yazılı tarif için:" link is followed (≤ 2 links, social/video/shortener/profile hosts skipped, shorteners expanded only when needed, HEAD with 5 s and ≤ 3 redirects, all through the guarded fetch). A schema.org/Recipe with ingredients and steps becomes the draft without an LLM call; provider `web` (also used now for a pasted recipe-site link, which used to report `rules`). The video stays the Kaynak; the page is `writtenRecipeUrl` ("Yazılı tarif" on the recipe page). Data: import provider `web` + `writtenRecipeUrl`, migration v9, Supabase enum/column; Ayarlar counts it as "tarif sitesi".
- **Boilerplate stripped before structuring** (both paths) and **never allowed as a step** (prompt rule + validator + pipeline filter). An empty Hazırlanış gets the calm hint on the review screen. Matching lower-cases with the Turkish locale first: plain `/i` doesn't fold "İ", which would have let "İndirim kodu" and "İnstagram" through.
- **Live check found one more cause:** Yemek.com's JSON-LD groups `recipeIngredient` as nested arrays per sub-recipe, which our reader saw as zero ingredients, so "ingredients and steps" failed and the page was skipped. The reader now flattens nested lists. The page also states `prepTime: PT1M` (placeholder) and a 46-min total that excludes the 2-hour marinade: a prep under 5 min with 6+ ingredients counts as unknown, and a total shorter than the waiting isn't reduced by it.
- The real description isn't copied into the repo: fixtures 16/17 are written in the same shape (written-recipe link, ingredients, no steps, chef profiles, socials, sponsor shorteners).

## Round 2.2 — Shorter recipe form

- **Order:** Genel (Tarifin adı, Öğün) → Malzemeler → Hazırlanışı → "Ayrıntılar" (three native `<details>`: "Süre, porsiyon, etiketler", "Ön hazırlık", "Kaynak ve artarsa") → Kaydet. Hazırlanışı moved above the optional parts so everything a phone user must touch comes first.
